# Implementation Plan: PWA Service Worker, Web Push & Announcements Inbox (F02-3)

**Branch**: `046-f02-3-sw-push-inbox` | **Date**: 2026-10-30 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/046-f02-3-sw-push-inbox/spec.md`

## Summary

Swap the PWA service worker from Workbox `generateSW` to `injectManifest` (`src/sw.ts`) to handle `push`, `notificationclick` and `pushsubscriptionchange`; add a per-device "Push notifications" control in `/profile/settings`; add an "Announcements" inbox under `/profile` with an unread badge on the Profile tab and tile; and keep the device push subscription in sync with the backend on every load and after VAPID/subscription rotation. Pure PWA client slice consuming the INSP-scoped routes shipped by TASK-F02-1; no backend, schema or new persisted entity. TDD throughout; `test-pwa-e2e` kept green by adding boot-call stubs to `BASELINE_STUBS` in the same PR.

## Technical Context

**Language/Version**: TypeScript 5.6 strict, ES2022 ESM; Node.js 24; pnpm 9 + Turborepo
**Primary Dependencies**: React 18, Vite 5, React Router 6, TanStack Query 5, `vite-plugin-pwa@^0.21` (Workbox 7), `@properfy/shared`, `openapi-fetch`; new devDeps `workbox-core/precaching/routing/strategies/expiration` (`^7.3.0`, matching the plugin's bundled Workbox)
**Storage**: Browser `PushManager` subscription + Cache Storage (Workbox runtime caches, unchanged names). No DB. React Query cache for the inbox.
**Testing**: Vitest + Testing Library (unit/component, jsdom with injected `PushManager`/`Notification`/`navigator.serviceWorker`); Playwright `test-pwa-e2e` (hermetic, Chromium + WebKit) kept green via `BASELINE_STUBS`; manual device QA (Android installed + iOS ≥ 16.4 installed) as the push acceptance gate.
**Target Platform**: Installed PWA on Android Chrome and iOS 16.4+ Safari; also usable in-browser (iOS Safari → `ios-needs-install`).
**Project Type**: Mobile PWA (`apps/pwa`) in a monorepo.
**Performance Goals**: No regression to current precache/offline behaviour; SW bundle must not pull in zod/schemas (tree-shaken shared allowlist import only).
**Constraints**: `logout` stays synchronous; iOS requires permission in a gesture and a shown notification per `push`; offline navigation fallback preserved; `dist/sw.js` path unchanged for seamless rollback.
**Scale/Scope**: ~44 files, ~8 steps; single PR targeting `develop`, ≤ 150 files.
